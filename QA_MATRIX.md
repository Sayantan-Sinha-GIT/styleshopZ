# styleshopZ release QA matrix

This is an end-to-end **prototype** marketplace. The checks below use disposable accounts, sample products, Razorpay test mode and Demo Courier. They do not book real parcels or charge real money. A finite test run cannot cover every device, provider outage or future state, so the release report records the exact checks run and any remaining boundaries.

| Area | Normal flow and unusual/hostile cases exercised | Repeatable check |
| --- | --- | --- |
| Identity | Registration, duplicate email, wrong password, verification codes (wrong/expired/reused), password reset, Google identity, login/logout, stale/tampered session, owner-only route, role escalation, account deletion and session revocation | `npm run test:integration`, `npm run test:discovery`, `npm run test:browser`; owner confirmed Google and Brevo delivery on their device/inbox |
| Discovery | All seeded categories, search synonyms and typo recovery, long/empty terms, sorting, price/rating/brand/discount/stock filters, pagination, unavailable products, variants and comparison | `npm run test:discovery`, `npm run test:browser` |
| Cart and checkout | Guest persistence/merge, quantities, wishlists, saved items, invalid coupon, address requirement, Ola lookup/manual address, forged price/quantity, expired or foreign stock hold, idempotent retry, duplicate callback, late payment, 50 buyers for 10 units | `npm run test:integration`, `npm run test:management`, `npm run test:browser` |
| Payments | Demo and COD order, Razorpay test order and hosted UI, invalid signature, malformed/duplicate/delayed captured webhook, pending cancellation, discount apportionment, refund and ledger | `npm run test:integration`, `npm run test:browser`; historical sandbox capture/refund recorded in `TEST_REPORT.md` |
| Orders and delivery | Shopper order visibility, invoice, cancellation once, seller packed/shipped/out-for-delivery/delivered sequence, tracking, invalid transition, reorder, verified review/question | `npm run test:integration`, `npm run test:management`, `npm run test:browser` |
| Returns | Seven-day eligibility, foreign order/item rejection, duplicate request, private evidence ownership, seller/admin review, approve/reject, partial discount rounding, concurrent returns, single stock restoration, refund and notification | `npm run test:integration`, `npm run test:browser` |
| Seller | Approval, KYC privacy, product/variant CRUD, image ownership and private-image exclusion, stock while held, CSV failures, shop/profile, order fulfilment and seller-specific support | `npm run test:management`, `npm run test:support`, `npm run test:support:browser`, Flutter widget tests |
| Owner | Owner-only sign-in and sign-out to the private entrance, shopper/seller exclusion, user/seller management, category/coupon/deal/banner moderation, reviews/Q&A, returns, notifications and audit trail | `npm run test:management`, `npm run test:browser`, `npm run test:support:browser`, Android emulator |
| Support | Eight issue types, optional own-order link, seller case, private photo evidence, missing/foreign/public/duplicate/oversized photo, malformed or overly long text, XSS displayed as text, cross-account read/write denial, owner-only internal note and priority, public reply notification, status transitions and reopen-before-reply, search/status/category filters, 37-ticket pagination, rate limit and concurrent replies | `npm run test:support`, `npm run test:support:browser`, `npm run test:browser`, Flutter widget tests |
| Resilience and accessibility | Phone/desktop widths, light/dark and reduced-motion modes, long Unicode content, corrupt local state, network failure recovery, no horizontal overflow, Android system-bar clearance | `npm run test:browser`, `npm run test:support:browser`, emulator inspection |
| Security and release | Owner/customer/seller authorization, CSRF and non-JSON rejection, private uploads, export without secrets or internal support notes, dependency audit, tracked-file and signed-APK secret scan | `npm run test:integration`, `npm run test:support`, `npm audit --audit-level=high`, release scan |

For a local replay, configure `.env.local` using `SETUP_GUIDE.md`, start the production build (`npm run build` then `npm start`), and run the commands in the table. Browser checks need Chrome; set `CHROME_PATH` if it is not in the default Windows location. Integration checks create isolated QA data in the configured database and clean it afterward. The browser suites write screenshots and results to ignored `.qa/`.

External service availability, real shipping, live payment settlement, seller payout and Play Store distribution are outside this demo. The native owner APK is for private owner control; shoppers and sellers should use the Flutter APK.
